# Announcements

The website's Latest Announcement popup and `/announcements` page use the existing `news_categories` and `news_content` tables. External media coverage remains separate.

After deploying this update, run `npm run announcements:enable` once to add the announcement permissions and nullable UTC `publish_at` column without changing existing content or running unrelated migrations. News requests also ensure this additive column exists. Fresh databases receive the column and permissions through `npm run db:migrate`.

Admin → Announcements → Categories manages categories. Admin → Announcements manages notices, optional images and read-more URLs. Drafts hide publishing choices and date/time controls. Selecting **Published** reveals two timing options directly beside Publish Status: **Publish immediately** or **Choose date and time** in **IST (Asia/Kolkata, UTC+05:30)**. Both fields are optional: leaving both blank publishes immediately, a date alone uses midnight IST, and a time alone uses today's IST date. Future notices show **Scheduled**, and the save button becomes **Schedule Announcement**. Drafts never appear publicly or show a publish date in the admin table. Cancel Schedule returns a notice to Draft. Publishing a draft from the list publishes it immediately; use Edit to set a schedule.

The API accepts optional `date` and `publish_time` (`HH:mm`) as IST wall-clock values and `publish_immediately: true` for immediate publication. New blank timing uses the server's save instant; draft saves require no timing. Switching a future schedule to immediate uses the save instant, while editing an already visible notice in immediate mode preserves its original timestamp. Older clients omitting timing on an existing record preserve it. UTC persistence and `publish_at`, IST `publish_time`, and `publication_state` readback remain unchanged. A notice becomes eligible on the exact second of its schedule, without a cron job or manual status update. Only published notices in active categories whose instant has arrived are included. The popup shows the newest three; the full page reads all pages of the feed. Instants sort descending with ID descending for ties. Existing date-only records retain midnight IST.

`GET /api/news/public` is anonymous and always enforces publication, category status and schedule filters. Query parameters cannot override them. It supports `page` and `limit` (maximum 100). Other `/api/news` reads and writes require authentication and the corresponding `news.category.*` or `news.content.*` permissions. Publishing, unpublishing and rescheduling a published notice require `news.content.publish`. The admin list can filter Draft, Scheduled or Published.

The website reads the API using `API_BASE_URL`. Its same-origin `/api/announcements` handler loads the three latest notices for the popup without exposing server configuration. Both feeds bypass caching. The open popup, Announcements page and admin list refresh every 30 seconds while visible; the website also refreshes when its window regains focus. Empty feeds show an empty state, and an API failure shows an unavailable message with a retry button in the popup. Demo content never replaces published or unavailable data.

Checks: `node --test test/announcements.test.js`; website: `node --test test/announcements.test.mjs`.
